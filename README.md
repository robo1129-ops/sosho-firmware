# SO-SHO ファームウェア

SO-SHO分割キーボード用のZMK構成と専用拡張です。日常構成は右側Central＋トラックボール、左側Peripheral＋トラックパッドです。

## 接続と設定
- PCへの文字・マウス入力はBluetooth経由です。USBは充電と右側Centralの設定通信に使用します。
- [Webキーマップエディター](https://robo1129-ops.github.io/sosho/)で、右側のUSBまたは対応するBLE接続から読み取り・編集・保存します。
- Windowsで直接BLE接続できない場合は、Webページで配布するWindows BLEブリッジを利用します。OSやブラウザーの制限をファームウェアだけで解除するものではありません。
- 保存後は実機から再読み取りし、一致を確認してください。ブラウザー内の表示変更だけでは実機への保存完了になりません。
- 最新の公開ZIPはWebページから取得できます。公開済みZIPは、その公開時点のビルドです。手元で追加修正中の成果物が自動で含まれるわけではありません。

## キー・レイヤー
通常キー、修飾キー、メディア操作、マウス操作、Bluetooth接続先操作、レイヤー操作に対応します。通常編集用はLayer 0〜9、スクロール用はLayer 10です。保存済みキー配列は初期化せず引き継ぎます。

タップ／ホールドは280ms、同一キーの再押下猶予は300msです。判定前に修飾キーやレイヤーを仮押下しません。別キーを含む押下・解放と時間経過からホールドを決定するbalanced方式を使います。一度タップして離した直後に同じキーを長押しすると、タップ側のキーが押され続けます。最初から長押しするとホールド側が動きます。

日本語配列の半角／全角には修飾なしのGRAVE（HID usage 0x35）を使用します。Alt＋GRAVEは別の組み合わせです。実際のIME切り替えはOSのキーボード配列とIMEにも依存します。

## ロータリーエンコーダー
左右各エンコーダーの回転方向ごと、レイヤーごとに割り当てを保存します。初期値は左が横スクロール、右が縦スクロールです。Webのエンコーダー欄から変更し、保存・再読み取りしてください。未設定レイヤーはLayer 0を引き継ぎ、明示的に設定したレイヤーではその設定が使われます。

専用のsosho_encoder動作が回転を受け取り、sosho_encoder_runtimeが保存済み割り当てを解決します。実際の動作は右Centralが所有します。エンコーダー自身を回転先の動作に指定する循環割り当ては拒否します。

保存先はsosho_runtime/encoder_bindingsです。2026年11月21日の修正ではスリープ設定と読み込みハンドラーが競合する問題を解消し、同じ保存先の既存データを読み込めるようにしました。保存成功後にだけ実行中の割り当てを更新します。現在の修正について、長時間使用・再起動後の実機確認は別途必要です。

## ポインティングと省電力
右トラックボールはPMW3610、左トラックパッドはPinnacleの相対モードを使います。CPI、トラックパッド移動倍率、スクロール量の実行時調整は専用RPCで扱います。軸方向やセンサー構成はビルド設定です。

現在の日常用ビルドは無操作30分でアイドル省電力へ移行し、深いスリープは無効です。右トラックボールにはforce-awakeを指定し、センサー独自の128msダウンシフトによる早期省電力を抑えています。30分待機からの復帰は実機確認が必要です。

キー通知は一時的な送信待ちで押下・解放の順序を維持して再送します。キュー容量は有限であり、切断中の入力を無制限に記憶する機能ではありません。ポインター通知は小分けに送り、キー通知が待たされる時間を減らしています。

トラックパッドは短いタップによる左クリックに対応します。右クリックの長押し判定・外周スクロール・多指操作は現在の日常構成には含めていません。右側トラックパッド構成では物理方向に合わせてX/Yを反転します。

## マクロ・その他
マクロは16枠、各最大64ステップ・512バイトです。キーの押下・解放・待ち時間とBluetooth接続先操作を専用RPCで保存します。設定保存領域はキーマップ等と共用です。連続実行や長い待ち時間を含むマクロは実際の接続先切り替えを含めて確認してください。
タップダンスの新しい動作定義はビルドが必要です。左ブートローダー操作、バッテリー低下時の青点滅などの専用動作は各ソースに含まれます。

## Windowsでのローカルビルド
Python・west、CMake、Ninja、Arm GNU Toolchainを用意し、リポジトリ直下で実行します。

```powershell
.\windows-build\build-windows.ps1 -Shield sosho_R_trackball -NoUpdate -SleepMode off
.\windows-build\build-windows.ps1 -Shield sosho_L_trackpad -NoUpdate -SleepMode off
```

生成先はbuild-windows/<構成名>/zephyr/zmk.uf2です。SleepMode offは深いスリープを無効にし、30分のアイドル省電力とは別です。ビルドスクリプトはZMKと関連モジュールへpatches内の変更を適用します。

その他の構成にはsosho_R_trackpad、sosho_L_trackball、sosho_R_none、sosho_L_noneがあります。日常構成以外はそれぞれのビルド・実機検証が必要です。settings_resetは設定消去用であり、通常更新では使用しません。

## 書き込みと確認
左右それぞれをブートローダーモードにし、対象の側に対応するUF2だけをコピーします。正常コピー後はブートローダードライブが消えます。右側は通常USBの再認識も確認します。ドライブ消失だけでは文字入力・無線接続・保存内容の実動作まで証明できません。

更新後はキー入力、タップ／ホールド、両エンコーダー、ポインター、設定の保存・再読み取り・再起動後の保持を確認してください。保存済み設定の初期化は通常不要です。

## 容量・配線・ライセンス
XIAO nRF52840のアプリ領域は788KiB、設定保存領域は32KiBです。UF2サイズには管理情報が含まれるため、容量はビルドログのFLASH/RAM使用量で確認します。NVSの実際の残量は既存の保存内容にも依存します。

トラックパッド選択はP1.05、トラックボール選択はP1.03、データ準備信号はP1.07です。配線定義はboards/shields/sosho以下、参照した製造元資料は[SO-SHOのFAQ](https://elekit.co.jp/support/faq/5255)です。
